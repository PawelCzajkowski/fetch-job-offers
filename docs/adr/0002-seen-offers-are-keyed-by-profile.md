# Seen offers are keyed by profile, not globally or by saved search

An offer counts as seen under a profile, not globally and not per saved search: `seen.json` stores each offer's data once by LinkedIn job ID, and stores verdicts under the normalised profile text (whitespace trimmed and collapsed, case ignored). A verdict depends only on the offer and the profile it was judged against, so this is the key that matches the decision. A global key would stop a TypeScript search from ever judging an offer a Java search had rejected. A per-search key would show and pay for the same offer twice when two searches share a profile. As a consequence, editing a profile's wording deliberately makes offers new again under the new wording, so no stale-verdict detection is needed, and ad-hoc searches (which have no name) are keyed the same way. After a prompt or model change, the intended reset is deleting `seen.json`, because `--rejudge` only retries unjudged offers.
