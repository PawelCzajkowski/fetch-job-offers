# Visited offers live in their own file, not in seen.json

Visited marks are kept in their own file (`visited.json`, configurable like `seenStore`), not as a field on each offer in `seen.json`, even though both are keyed by LinkedIn job ID. The two files have different writers: a run loads `seen.json` at the start and rewrites the whole file after each search, while `fjo serve` writes a visited mark whenever the user ticks one in a report. If both lived in one file, ticking an offer while a run was in progress would be silently lost when the run saved its older copy. Separate files also keep the documented reset intact: deleting `seen.json` to judge everything again must not wipe the user's own marks. The cost is a second file to configure and ignore, and visited marks for offers that `seen.json` no longer knows about, which are harmless and are never pruned.
