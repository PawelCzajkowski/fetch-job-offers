# Work mode and seniority are LLM judgments, not request filters

LinkedIn's guest search endpoint accepts `f_WT` (work mode), `f_E` (seniority) and `f_JT` (job type) as documented-looking query parameters, but real requests (see the research on [Which search criteria can LinkedIn's guest endpoints filter in the request?](https://github.com/PawelCzajkowski/fetch-job-offers/issues/2)) showed they're silently ignored: results are identical with or without them. Only `keywords`, `location`/`geoId`, `distance` and `f_TPR` (date posted) actually narrow the search. So the tool over-fetches every offer matching title, location and date, and has the LLM judge work mode from the offer's text as part of its verdict call, rather than trying to pre-filter on a parameter that doesn't work. Seniority is handled the same way: the detail page has a structured "Seniority level" field, but it's frequently "Not Applicable" even for roles clearly titled "Staff" or "New Grad", so the tool ignores that field and always has the LLM read seniority from the title and description instead.
